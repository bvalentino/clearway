## Architecture decisions carried from the spec

- D1/D2: the CLI link is `~/.clearway/cway`, an absolute symlink to `<bundle>/Contents/MacOS/cway`.
  The skill always runs `~/.clearway/cway`, never bare `cway`.
- D3: the skill lives in the repo at `Skills/clearway/SKILL.md`, added to the `Clearway` target
  under `sources:` as `- path: Skills`, `type: folder`, `buildPhase: resources`. It lands at
  `Contents/Resources/Skills/clearway/SKILL.md`. Not under `Sources/` (its `**/*.md` are excluded),
  and not via the target-level `resources:` key (xcodegen ignores it).
- D4: Claude Code is gated on `~/.claude` being a directory; its link is
  `~/.claude/skills/clearway`, creating `skills` if missing. Codex is gated on `~/.codex` being a
  directory; its link is `~/.agents/skills/clearway`, creating `~/.agents/skills` if missing.
  Clearway never creates `~/.claude` or `~/.codex`. `CLAUDE_CONFIG_DIR`/`CODEX_HOME` are ignored.
- D5: an entry is Clearway's when it is a symlink (checked without following it) whose destination
  string ends in `.app/Contents/Resources/Skills/clearway` (skill entry) or `.app/Contents/MacOS/cway`
  (CLI entry). The target need not exist.
- D6: entry states are `agentAbsent` (skill entries only), `missing`, `current`, `stale`, `foreign`.
  Always read from disk; nothing is stored.
- D7: Install, per entry whose gate exists: `missing` → create link (and `~/.clearway` mode `0700`
  or the `skills` directory as needed); `stale` → remove and recreate; `current` → nothing;
  `foreign` → untouched. One entry failing does not stop the others. The CLI link installs even with
  neither agent present.
- D8: Uninstall removes every `current` or `stale` entry and nothing else, and removes no directory.
- D9: installed = no entry `missing` or `stale`, and at least one `current`. `foreign` and
  `agentAbsent` do not block it.
- D10: Settings gets a section headed "Agents" with one row, `LabeledContent("Clearway Skill")`, and a
  button "Install" or "Uninstall" per D9. Under it, only when non-empty, red lines styled like the
  hook health line: "`~/<path>` already exists and was left alone." per foreign entry, or "No
  ~/.claude or ~/.codex directory was found, so the skill was not installed." when both gates are
  absent. State read on appear and after each action. No helper text.
- D11: nothing installs at launch. Only the Settings button calls install/uninstall; no test calls
  them with the real home directory.
- D12: `enum SkillInstaller` in `Sources/App/SkillInstaller.swift`, Foundation only, no actor
  isolation; every function takes `home: String` and `bundlePath: String`.
- D13: `SKILL.md` frontmatter has `name: clearway` and `description` only. Body content as listed
  in D13.
- D14 (operator-confirmed): `TaskFiles.loadPool` also reports skipped files; `cway task list` and
  `task show` print `cway: warning: skipped '<path>': <reason>.` per skip on stderr, keep stdout and
  exit code; the app ignores the list.
- D15: Install from a Debug build points the links at the Debug bundle.

## Tasks

### T1: Warn on stderr for skipped task files

**Files:** `Sources/Shared/TaskFiles.swift`, `Sources/Shared/TaskCommand.swift`,
`Sources/App/WorkTaskManager.swift`, `Tests/TaskFilesTests.swift`, `Tests/TaskCommandTests.swift`.

**What:**
- `TaskFiles.loadPool(tasksDirectory:worktreePaths:)` returns both the pool and the skipped files,
  each skip carrying its path and a reason. A small struct (for example `LoadedPool { tasks; skipped }`
  with `Skip { path; reason }`) is the expected shape; pick names that read well at the three call
  sites.
- A skip is recorded for: a tasks directory that exists but cannot be listed; a `<UUID>.md` in it
  that cannot be read (or is not UTF-8) or does not parse (`WorkTask.parse` returns nil); a worktree
  `TASK.md` that exists but cannot be read, does not parse, or has no frontmatter `id`.
- Not a skip: a missing tasks directory, a missing `TASK.md`, a non-`.md` file, or a `.md` whose
  name is not a UUID. Check existence before reading so a missing file is not reported.
- `TaskFiles.load(atPath:fallbackId:requireFrontmatterID:)` keeps its signature and nil-on-failure
  behaviour for its two other callers (`WorkTaskManager.swift:195,198`); route the reason through a
  variant that `loadPool` uses and `load` wraps.
- Reason wording (fixed here; the spec leaves it open): `cannot list the directory`,
  `cannot read the file`, `cannot parse the frontmatter`, `its frontmatter has no id`.
- Skips are ordered by path so output is deterministic.
- `TaskCommand` `list` and `show` prepend one `cway: warning: skipped '<path>': <reason>.\n` line per
  skip to `Result.stderr`, keeping stdout and exit code unchanged. When `show` fails with "no task
  with id", the warning lines still print, before the error line: the skipped file may be the task
  asked for. `create` is unchanged.
- `WorkTaskManager.reload()` takes the tasks and ignores the skips. Update the existing
  `TaskFilesTests` call sites.

**Acceptance criteria:**
- `loadPool` reports each of: an unreadable `<UUID>.md` (mode `000`), a `<UUID>.md` with no
  frontmatter, an id-less `TASK.md`, an unlistable tasks directory (mode `000`); and reports nothing
  for a missing `TASK.md`, a missing tasks directory, or `notes.md` in the tasks directory. Valid
  tasks alongside the skips still load. Restore permissions in the test before teardown.
- `cway task list` and `task show <id>` with a skipped file present: exit 0, stdout decodes as before,
  stderr is exactly the warning lines. `show` of an absent id with a skip present: exit 1, stderr is
  the warning lines followed by the existing not-found message.
- With no skips, `list`/`show` stderr stays `""` (existing tests unchanged).

**Verify:** `./scripts/ci.sh` exits 0 after the last edit.

### T3: SkillInstaller

**Files:** `Sources/App/SkillInstaller.swift` (new), `Tests/SkillInstallerTests.swift` (new),
`Clearway.xcodeproj/project.pbxproj` (regenerated), `Sources/App/CLAUDE.md`.

**What:**
- `enum SkillInstaller` per D5-D9 and D12. Expected surface (names may change, shape should not):
  `status(home:bundlePath:) -> SkillInstallStatus`, `install(home:bundlePath:)`,
  `uninstall(home:bundlePath:)`. The status holds one entry per path (CLI, Claude Code, Codex) with
  its D6 state and its home-relative display path, plus `isInstalled` (D9) and the D10 warning
  lines (`messages: [String]`), so the view does no logic and the strings are tested here.
- Paths: CLI link `<home>/.clearway/cway` → `<bundlePath>/Contents/MacOS/cway`; skill links
  `<home>/.claude/skills/clearway` and `<home>/.agents/skills/clearway` →
  `<bundlePath>/Contents/Resources/Skills/clearway`. Absolute destinations.
- Inspect entries with `FileManager.attributesOfItem` (does not follow links) and
  `destinationOfSymbolicLink`; never `fileExists` on the entry itself, which follows links and
  misreports a dangling one as missing.
- Create `~/.clearway` with `posixPermissions: 0o700` when absent; create a `skills` directory (and
  `~/.agents`) only when its gate exists. Never create `~/.claude` or `~/.codex`.
- Per-entry failures are caught and do not stop the other entries.
- Tests use `TempRootTestCase`'s `tempRoot` as `home` and a fake bundle `<tempRoot>/A.app` with
  `Contents/MacOS/cway` and `Contents/Resources/Skills/clearway/SKILL.md`. Cover spec Testing T1-T8:
  both gates; only `~/.claude` and only `~/.codex` (no `~/.agents` created in the first); neither
  gate (CLI link made, both skills `agentAbsent`, the "No ~/.claude or ~/.codex" message); foreign
  real directory, real file and unrelated symlink at each entry left untouched by Install and
  Uninstall and reported with the D10 line; stale link to `<tempRoot>/B.app/...` and a dangling link
  repointed by Install and removed by Uninstall; Uninstall leaves siblings and the `skills`
  directories; the D9 state matrix including installed-with-foreign and stale-blocks-installed;
  Install twice is a no-op the second time.
- `Sources/App/CLAUDE.md`: a per-file note for `SkillInstaller.swift` (what is Clearway's, why state
  is never stored, why there is no launch call).

**Acceptance criteria:**
- All listed cases pass against the temp root; no test touches the real home directory.
- No call site of `install`/`uninstall` exists outside the tests yet.
